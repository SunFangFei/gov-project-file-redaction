# 政府信息化文件脱敏规则

## 强度

| 强度 | 典型场景 | 默认处理 |
| --- | --- | --- |
| 轻度 | 委内流转、内部预审 | 删除个人联系方式、证件号、账号密钥；保留项目、单位和金额 |
| 标准 | 上传外部 AI、跨单位评审 | 替换项目、非公开单位、供应商、人员、地址、网络标识；金额策略单独确认 |
| 严格 | 公开发布、对外招采前交流 | 在标准基础上处理精确金额、日期、资源规模和可组合识别信息 |

## 字段分级

### S1：必须处理

- 身份证、护照、银行卡、社保卡、病案号及其他唯一身份标识。
- 手机、私人邮箱、家庭住址、签名、手写批注。
- 用户名、密码、Token、密钥、连接串、内网域名、私有 IP、设备序列号。
- 未公开患者、医生、专家、联系人和评审人员信息。

### S2：按场景处理

- 项目全称、建设单位、使用单位、实施单位、供应商和产品型号。
- 医院、街镇、科室、机房或具体部署地址。
- 合同号、项目编号、采购编号、内部文号、时间计划。
- 单价、合价、总价、预算金额、折扣率、核增减额、专家意见与厂商响应。
- 数据规模、并发、资源配置等可与公开信息组合定位项目的参数。

### S3：通常保留

- 国家、上海市及区级公开政策文件名称和文号。
- 通用技术术语、功能模块、建设原则、验收方法。
- 对评审核心有必要的性能、数量和投资结构，但严格模式下可区间化。

## 替换策略

| 类型 | 推荐替换 |
| --- | --- |
| 项目 | 项目A、项目B |
| 建设/使用单位 | 建设单位A、使用单位A |
| 厂商 | 供应商A、供应商B |
| 人员 | 联系人A、专家A |
| 医疗机构 | 医疗机构A |
| 区域/街镇 | 某区、街镇A |
| 电话/邮箱 | `[手机号已脱敏]`、`[邮箱已脱敏]` |
| IP/域名/账号 | `[网络标识已脱敏]`、`[账号已脱敏]` |
| 编号 | 项目编号A、合同编号A |

同一批次稳定映射，保留实体间差异。不要用同一个“某单位”替换所有主体，否则会破坏建设单位、使用单位和供应商之间的关系。

## 金额策略

| 策略 | 处理方法 | 适用场景 |
| --- | --- | --- |
| 保留 | 金额原值不变，只脱敏主体 | 仍需投资评审、对账、核价 |
| 统一比例缩放 | 金额统一乘以同一系数，并按原币种精度舍入 | 需要保留结构和占比但隐藏真实规模 |
| 区间化 | 精确金额替换为区间；同步修改正文表述 | 阅读、示例、培训材料 |
| 完全移除 | 用“金额已脱敏”替代，删除公式结果 | 金额本身高度敏感且无需评审 |

比例缩放时：数量通常保持不变；单价、合价、小计、总计、税额、核增减额、优惠额和正文金额同步处理；百分比和折扣率原则上保持不变。舍入差额应集中调整到明确记录的一项，禁止静默分散修改。

不得随机逐格修改金额。金额处理后必须重新核对总表、分表、正文、PPT或附件间的一致性。

## 组合识别风险

单个字段可能公开，但“行政区划＋项目名称＋精确金额＋建设周期＋供应商型号”的组合可能定位具体项目。严格模式应评估组合识别，而非只匹配身份证和手机号。
